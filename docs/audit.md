# Audit of the rules on a real specification

Every rule was run on the Zitadel API specification (`bundled/openapi.json`, OpenAPI 3.1, 78 paths, 96 operations, 44 webhook operations) and on the multi-file `openapi-spec.yaml` it is bundled from. For each rule that reports, a sample of at least five findings (all when fewer), spread over different locations, was opened in the spec and judged against the rule's documented intent. For each rule that stays silent, the spec was checked by hand against the rule (at least three spot checks, or proof that the feature is absent), and rules that need options were run with options set.

Verdicts: **CORRECT** the findings are true positives; **STRICT-BY-DESIGN** the findings follow the rule's documented intent but are noise for this spec, and an option may relax them (the notes say which, or that none exists); **BUG** the logic was wrong (fixed, or marked open); **CORRECT-SILENCE** the spec satisfies the rule or lacks the feature; **INERT-WITHOUT-OPTIONS** the rule needs options to do anything. The sample verdicts are judgments made by reading the spec, not a review of every finding.

"Now" counts are from the bundled spec after the fixes of this branch (3877 findings from 67 rules); "Before" counts are from the first run (4733).
